# 第一份工作教我的事

现在回头看，第一份工作给我的技术资产早就过时了
（那家公司用的框架，如今官网都 404 了），
但有几个**职业习惯**是那时候烙下的，受用到现在。
写下来，给正在第一份工作里晕头转向的你。

## 一、提问前先自己查十分钟

带我的老哥第一句话：「百度能查到的别问我」。
当时觉得冷漠，后来知道是慈悲 ——
**搜索引擎是最慷慨的同事**，24 小时在线，
还从不嘲笑你的问题蠢。

十分钟查不到再问，这时候问题也具体了：
「我查了 X 和 Y，试了 Z，还是不行」vs「这个怎么弄」——
前者三分钟得到答案，后者得到一句「自己先查查」。

## 二、提交前自己先读一遍 diff

第一次提 PR，被 review 出三个低级问题：
`console.log` 没删、变量名拼错、注释是废话。
老哥说：「你自己看过一遍，这些都不会发生」。

现在我 commit 前必 `git diff`。**自己都不好意思
交出去的东西，别指望别人不好意思说**。

## 三、「我不知道」比瞎编安全一万倍

会议上被问到没准备的点，第一次硬着头皮瞎编，
被当场技术打脸，那半小时是我职业生涯最漫长的。
第二次学乖了：「这块我没做过，但我猜是 X 思路，
会后确认了同步」—— 没人因此看轻我，
反而有人说「这小伙子实在」。

**技术人员的信用是复利，撒谎是透支。**

## 四、命名和注释是写给三个月后的自己

第三个月改自己两个月前写的代码，看不懂。
那节课不用人教，代码自己就会教。
现在写「当时觉得没必要」的注释时，
都会想起那个下午 —— 自己盯着自己的代码，
像看前任的脸：熟悉，但想不起名字。

## 五、先让流程跑起来，再追求优雅

第一个任务我想写得「完美」：抽象三层、注释齐、
设计模式用上。三天憋出 20 行，被老哥打回：
「先跑起来，丑没关系」。

真实世界**先 working，再 clean**。
本站的[重构笔记](../reading-refactoring.md)里说的
「两顶帽子」—— 第一份工作就模糊感觉到了，
只是没找到那句话。

## 六、抱怨解决不了任何问题

同事离职前天天骂代码烂、架构屎、需求乱。
他走后那些屎山还在，只是骂声没了。
**要么改变它，要么忍受它，要么离开它** ——
三个选择都比抱怨强。这个道理我用了很多年。

## 七、身体是革命的本钱，真的

第一年加班猛，久坐 + 外卖 + 熬夜，
第二年颈椎报警，看医生花了大几千，
还是买不来原来的脖子。
现在我的[工作流](../my-workflow-2026.md)
里「晚上不碰代码」的规矩， partly 是那时候种下的因。

## 八、如果重来一次

会对第一年的自己说：

1. **别怕问，但先自己查**（十分钟法则）；
2. **别追求完美，追求完成**；
3. **别熬夜，颈椎比 deadline 贵**；
4. **多记录**（那时开始写博客就好了，
   也不至于现在只有三年前的记忆）；
5. **对带你的老哥好点** ——
   他教你的时候，是在牺牲自己的产出。

## 小结

第一份工作的价值，一半在工资，一半在
**职业习惯的塑形**：怎么提问、怎么交付、怎么沟通、
怎么对待身体。这些习惯比任何框架生命周期都长。
如果你正在第一份工作的迷雾里，别慌 ——
你觉得「怎么跟我学的完全不一样」就对了，
**工作本来就是另一门课**。
