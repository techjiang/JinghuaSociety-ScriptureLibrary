# 我是怎么学一门新技术的

工作这些年，学过大大小小几十种技术：框架、语言、工具链。
踩过「教程看到吐还是不会用」的坑，也总结出一套自己的流程。
不一定科学，但对我有效。写出来，说不定对你有用。

## 一、先说两个反面教材

**「收藏式学习」**：看到好教程就收藏，收藏夹三百篇，
真看过的十分之一。知识焦虑缓解了，能力一点没涨。
**「完美准备式学习」**：想学 React，先把 JS 高级程序设计
从头啃一遍，再刷 TypeScript 体操，三个月后还没开始写 React。
准备永远不够，**开始永远最难**。

我的方法核心就一句：**尽快让最小可用版本跑起来，用问题驱动学习**。

## 二、四步流程

### 第一步：半天搭个能跑的最小 demo

学新东西第一天，目标只有一个：**写个「hello world」级别的东西，
让它跑起来**。

学 Vue：三天不碰单文件组件，先 `npm create vue@latest` 跑通默认页；
学 Docker：不读原理，先 `docker run hello-world` 看见成功；
学 Redis：先 `SET` 一个 key 再 `GET` 出来。

为什么：**跑通一次，信心就有了**。后面看文档，
每个概念都能挂到这个「跑通过的印象」上。
没跑过直接看概念，全是抽象名词，看完就忘。

### 第二步：带着问题读官方文档

跑通 demo 后，开始读文档 —— 但**不是从头读到尾**，
是「我想加功能，查怎么加」：

```text
demo 能跑了 → 想加个路由 → 查文档「Routing」
→ 想调接口 → 查「HTTP」→ 状态管理是什么？查「State」
→ 这个报错什么意思？搜 issue
```

问题驱动读文档，效率是通读的三倍，而且记得牢 ——
「我为了解决 X 查到的 Y」比「我读了第 7 章」深刻得多。

**官方文档优先**。第三方教程是「别人嚼过的」，
更新滞后、夹杂私货。官方文档是唯一权威源
（本站[学习路线](../learning-roadmap.md) 里列的 MDN、
Vue 官方都是这个思路）。

### 第三步：抄一个像样的项目

demo 会跑了，文档会查了，接下来是「照着抄一个完整项目」。
GitHub 上找个 star 高的开源项目，**从头抄一遍**：

- 不是复制粘贴，是看懂一行写一行；
- 抄的时候问自己：**他为什么这么写？换我会怎么写？**
- 抄完对比：差距在哪（架构？细节？工程化？）

这个阶段最慢，也最值。我抄 Vue 后台模板的时候，
才第一次理解「路由守卫」「权限控制」的真实用法 ——
文档里都写过，但抄一遍才内化。

### 第四步：写文章 / 做输出

最后一步，也是我最看重的：**把学的东西写成文章**。

写不出来 = 没真懂。我在[事件循环](../js-event-loop.md)那篇
自认为门儿清，一动笔发现「微任务清空的时机」一直糊着，
为了写明白回去查了一下午。**写作是学习效果的质检员**，
这句话我说过很多次，因为它真的管用。

产出不一定是文章 —— 给同事讲、录个视频、
在项目里用一遍，都算。**核心是「输出倒逼输入」**。

## 三、时间分配的经验

一个中等复杂度的技术（比如一个框架）：

```text
第 1 天：跑通 demo（半天就够）
第 1 周：跟着文档做功能，查着写
第 2-4 周：抄项目，用进真实需求
第 2 个月：写篇文章/讲一次，收尾
```

两个月能「上岗干活」，半年能「讲出设计思想」。
那些「21 天精通 XX」，通的是「知道有这东西」，
不是「能拿它吃饭」。

## 四、几个私货建议

**别同时学两门新技术**。并行学 React 和 Vue 的结果是
两个都半吊子，还互相混淆（我干过，别学）。

**英语是隐形加速器**。官方文档、issue、Stack Overflow
都是英文。看得懂原文，你的信息源就比只看翻译的多十倍，
还快。本站有篇[英语学习](../english-for-devs.md)，自产自销。

**允许自己「不求甚解」**。第一遍看不懂的（比如 Vite 的
插件系统），标记一下先跳过，用到再回来看。
第一遍就抠细节，大概率抠到放弃。

**找「学习搭子」**。跟人约定一起学，每周对账。
一个人容易懒，两个人能互相拽着走。

## 五、写在最后

这套流程的本质：**先跑起来建立信心，再用问题牵引查文档，
接着抄项目内化，最后写文章固化**。它不快，
但每一步都扎实。慢就是快 —— 这句话俗，
但被我验证过很多次。

你现在想学什么？拿这套流程套一套，从「跑通 demo」开始。
今天就开始，别等下周一。
