# 工具疲劳：我为什么不再折腾新轮子

我的技术生涯可以切成两半：前半段热衷尝鲜，
后半段趋于保守。转折点不是「学不动了」，
是某天算了一笔时间账，发现自己
**花在「换工具」上的时间，比「用工具干活」的还多**。

这篇是「折腾腻了」的人的自白。

## 一、那些年折腾过的「神器」

按时间线回忆（不完全统计）：

- **编辑器**：Sublime → Atom → VS Code →
  （Cursor 试了三个月，回 VS Code）；
- **终端**：iTerm → Hyper → Warp → 回到
  Windows Terminal；
- **笔记**：Evernote → 为知笔记 → OneNote →
  Notion → Obsidian → 现在 Obsidian + Markdown；
- **博客**：WordPress → Hexo → VuePress；
- **框架**：jQuery → Angular → React → Vue →
  （Svelte/Solid 围观过，没用进项目）；
- **构建**：Grunt → Gulp → Webpack → Vite；
- **CSS**：Less → Sass → Stylus →
  CSS-in-JS → Tailwind → 现在原生 CSS 为主。

每一次迁移当时都有「这次真的更好了」的理由。
现在回头看：**一半是真进步，一半是「新玩具
眩目的错觉」**。

## 二、时间账：换个工具有多贵

不是「下载安装」那半小时。全成本：

```text
学习新 API/心智模型：      1-2 周（勉强能用）
达到旧工具熟练度：          1-3 个月
迁移存量项目/配置：          按项目规模，上不封顶
处理「新工具的坑」：         不可预估（这是大头）
队友/同事的学习成本：        × N
```

结论：**换个工具的真实成本以「月」计**。
人生有几个三个月？工具链稳定的人，
这些时间都在「产出」；我都在「搬家」。

## 三、什么值得换，什么不值得

不是守旧派。我的换工具标准（三条同时满足）：

1. **解决真问题**：不是「更优雅」，
   是「旧方案真解决不了」——
   比如 Webpack 冷启动 30 秒换 Vite（值）；
2. **迁移成本可承受**：新项目可以用，
   老项目别动；
3. **生态站住了**：star 过万、有商业公司背书、
   一年以上活跃度。**别做小白鼠** ——
   你踩的坑，就是后来人的教材，但不值得。

按这三条，我现在的「够用组合」：

```text
编辑器：VS Code（+ 少量插件）
终端：Windows Terminal + Git Bash
笔记：Obsidian
博客：VuePress + Plume
构建：Vite
语言：TS 为主
CSS：原生为主，需要工具链时 Tailwind
```

 boring 吗？ boring 就对了。**工具 boring，
产出才不 boring。**

## 四、新工具的正确围观姿势

不是说新东西不看 —— 不看的后果是「信息茧房」。
但「围观」和「迁移」是两回事：

- **看 release notes 和评测**：知道它解决什么问题；
- **玩具项目试一把**：周末写个 demo，
  感受下，但不碰生产；
- **放「观望清单」**：大多数放着放着就淡了 ——
  能被淡化的，本来就不重要；
- **真命天女出现才换**：当某个工具让你
  「旧方案的痛」每周出现三次以上，
  换。

## 五、更深一层：对抗的是 FOMO

折腾欲的本质是 **FOMO（错失恐惧）**：
「不用这个我会不会过时了？」

真相：**技术生涯的抗风险能力，
来自「深度」不是「广度」。**
一个领域挖到能教人，抵得上十个工具的
「熟练使用」。面试聊「我把 VuePress 部署
全链路自动化」比聊「我用过 20 个框架」
有说服力得多 —— 后者像收集癖，前者像工程师。

## 六、本站的「工具观」

技术客栈本身就是这套哲学的产物：

- 技术栈 boring（VuePress + Plume，成熟方案）；
- 没有花活（不追新插件、不堆特效）；
- 内容自己写（不 AI 洗稿）；
- 图自己画（SVG 手绘，丑但自有）。

**慢、笨、但每一寸都是自己的。**

## 七、什么时候打破它

最后留个后门：如果出现「代际差」工具 ——
比如 AI 编程助手让「不会写代码」的人也能
出活 —— 这种不是「更好的轮子」，
是「轮子变了」，该all in 就 all in。
判断标准还是那三条，只是第一条的
「真问题」权重调高。

## 小结

工具疲劳不是躺平，是**把「折腾」的激情
从工具层挪到问题层**：同样的时间，
花在「把事情做成」比「把工具换新」值。
本站会老，技术会旧 —— 但「能交付东西的人」
不会过时。

少折腾，多交付。与诸君共勉。
