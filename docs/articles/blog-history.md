# 我的博客迁移史

数了下，从初中到现在，正儿八经写过的博客有七个。
平台换了七八轮，文章丢了三轮。这篇是「忏悔录」，
也是「避坑指南」—— 给准备建站的你。

## 一、第一阶段：平台寄居（2009-2014）

### QQ 空间

初中主战场。装饰要黄钻、皮肤要代码刷、
访客量是社交货币。内容是「今天考试砸了」
「这首哥超好听」。**数据不属于你**——
几年后空间改版，日志排版全乱，回看像考古。

### 博客大巴 / 新浪博客

那会儿的「独立博客精神」是挂在嘴边的。
搬去新浪是因为「看起来正经点」。
结局：新浪博客关停公告那天，
我的四十篇「青春疼痛文学」成了数字难民。

**教训一：平台说关就关，你的数据只是它的库存。**

## 二、第二阶段：域名 + WordPress（2015-2019）

第一次拥有 `自己的域名`，用学生优惠买的。
WordPress 一键脚本，主题商城逛到眼花，
插件装了四十个（访问慢得像在传文件）。

那四年写了 100+ 篇，是巅峰。问题也来了：

- **服务器续费**：学生优惠到期，价格翻三倍；
- **维护地狱**：被挂马两次、数据库崩一次、
  插件冲突若干次 —— **每次修站都比写文章花的时间多**；
- **备份焦虑**：FTP 手动备份三个月一次，
  每次都忘了上次是什么时候。

**教训二：自建动态站，「运维」是隐形税，
按年征收。**

## 三、第三阶段：Hexo / Jekyll 静态化（2019-2021）

想通了：**我只是想写字，不想当运维**。
切到 Hexo，Markdown 写、静态部署到 GitHub Pages，
不买服务器、不怕挂马、速度还快。

 Hexo 的问题：主题丑（好看的收费）、
构建慢（文章过百要几分钟）、
Node 环境升级后各种包冲突。

**教训三：静态化是解脱，但生态老化是慢性病。**

## 四、第四阶段：VuePress + Plume（2022-至今）

本站。选型逻辑在[搭站教程](../build-blog-with-plume.md)
写过，不重复。这次「应该能稳定很久」的原因：

1. **内容是纯 Markdown**：平台死了，
   `git clone` 换个渲染器照样活；
2. **部署在 GitHub Pages**：免费、稳、
   自带全球 CDN、Actions 自动构建；
3. **配置进 git**：换电脑五分钟恢复；
4. **有 RSS 和 sitemap**：内容「可被带走」
   也「可被发现」。

## 五、丢过的文章与救回来的

最痛的一次：某平台关停，没导出，
三年文章全没。现在我的「防灾方案」：

```text
本地 Obsidian 写草稿（第一现场）
  → git 仓库（正文永久版本库）
    → GitHub 私有备份
      → 本站发布（公开层）
```

**教训四：内容资产要「本地优先、多点备份」，
发布层只是最后一环。**

## 六、给准备建站的你

如果这篇能穿越回去，我想对每个阶段的自己说：

1. **内容比平台重要一万倍**。再漂亮的主题，
   救不了没东西可写的仓库；
2. **Markdown 是内容的「普通话」** ——
   纯文本、任何工具能打开、git 能管；
3. **别沉迷折腾**。我统计过，
   花在建站上的时间够写五十篇文章；
4. **域名买十年**（别一年年续，忘续费被抢注的
   惨案年年有）；
5. **导出功能是刚需**：任何平台，
   先确认「能不能一键导出」再入驻。

## 七、下一步

不承诺「永远不迁」—— 但现在的状态我满意：
写作无摩擦（VS Code + Markdown）、
维护零成本（CI 自动）、数据有主权（git）。
等哪天 VuePress 也老了，`git clone` 走人，
新平台一贴，一天搞定。**这才是「不折腾」的底气：
内容是可迁移的。**
