# 我对静态站的执念

每当我劝人「博客用静态的」，总遇到一句：
「动态才灵活啊，能交互能评论能改数据。」

这话没错。但我还是劝静态 —— 这篇文章说说
一个被 WordPress 毒打过的人，为什么「一根筋」到底。
也说说静态站**不适合**什么（免得变成宗教）。

## 一、动态站的「拥有成本」

WordPress 时代的日常（别笑，真事）：

```text
周一：插件要更新，更新前备份，更新后白屏，回滚
周三：数据库连接错误，查日志，是主机商重启了 MySQL
周五：评论区 500 条垃圾评论，装 Akismet，配置规则
月底：服务器续费提醒，磁盘 80% 了，清日志清缓存
某天： 被挂马了，全站扫描，改密码，通知主机商
```

**我写了一年博客，运维了两年服务器。**
写作是乐趣，运维是服役。

## 二、静态站的「减法」

切到静态（VuePress）之后：

```text
写：VS Code 里写 Markdown
发：git push
没了。
```

没有数据库、没有运行时、没有插件冲突、
没有「半夜主机商重启服务」。服务器？
不需要 —— GitHub Pages 免费托。

**复杂度的消失不是巧合，是架构性的：**
没有可执行的服务端代码，攻击面趋近于零；
没有状态，就没有状态同步的 bug；
没有构建期之外的环节，就没有环节之间的裂缝。

## 三、失去的与补回来的

静态站砍掉了什么，怎么补：

| 失去 | 补法 |
| --- | --- |
| 评论 | Giscus（GitHub Discussions）/ Utterances |
| 搜索 | 本地搜索（本站 minisearch）或 Algolia |
| 动态内容 | 构建时生成（RSS、sitemap、文章列表） |
| 登录/个性化 | 基本不需要（内容站要什么登录） |
| 「改完立刻生效」 | CI 一两分钟 —— 内容站等得起 |

**评论区我选了不装** —— 不是不能，是问自己：
「真的需要吗？」大多数个人站的评论区，
最终变成垃圾广告 + 偶尔一条「感谢分享」。
真想交流的，GitHub issue 更认真。

## 四、静态站不适合什么（客观说）

不是万灵药。这些场景别硬上：

- **内容频繁变动**：股票行情、协作文档、后台系统；
- **多用户生产**（UGC）：社区、论坛 ——
  内容得存数据库；
- **重个性化**：每个人看到不同的页面；
- **需要服务端逻辑**：支付、鉴权、文件处理。

**判断标准**：你的页面是「发布时定型」还是
「请求时生成」？前者静态，后者动态。
博客/文档/官网/营销页 —— 都是前者。

## 五、更深一层：数据的主权

静态站的隐藏福利：**内容是你的**。

```text
80 篇文章 = 80 个 Markdown 文件 + 一个 git 仓库
```

- 换框架？文件复制过去，改改配置；
- 换托管？`git push` 到别家；
- 平台倒闭？跟你的文件没关系。

对比 WordPress：内容在 MySQL 里，格式带着
`<!-- wp:paragraph -->` 的痕迹，导出迁移掉层皮。

**「纯文本 + 版本控制」是这个时代最务实的数据主权方案。**
本站的[博客迁移史](./blog-history.md) 就是一部
「被平台毒打史」—— 看完你会理解这种执念。

## 六、成本账（再算一遍）

```text
静态站年度成本：
  域名：60 元
  托管：0（GitHub Pages）
  运维：0（没有可运维的）
  备份：git（分布式，天然）
  安全更新：无（没有要更新的服务）
───────────────────────
  合计：60 元/年 + 写文章的时间
```

动态站年度成本：服务器 300+、运维时间若干、
安全焦虑若干、**「服务器又挂了」的凌晨**。

## 七、所以

我对静态站的执念，本质是**对「可控」的执念**：

- 写作的流程可控（本地写完再发）；
- 内容的命运可控（文件在硬盘上）；
- 系统的复杂度可控（没有黑盒会突然坏）。

代价是「不够灵活」。但一个写东西的人，
要那么多灵活干什么？**笔和纸够了，剩下的都是借口。**
