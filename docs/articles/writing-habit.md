# 我的写作习惯：怎么坚持写

「你怎么坚持写博客的？」被问过不止十次。
我的答案可能让人失望：**不靠坚持，靠流程。**

我是程序员，不是文字工作者。靠「灵感」和「意志力」
写作的人，三个月就弃更了（见过太多）。
这套流程的精髓：**把「写作」拆成不用动脑的步骤。**

## 一、素材：平时攒，不现找

「不知道写什么」是弃更第一因。解法：**素材在日常，
不在动笔时。**

我的三条素材来源：

1. **踩坑即记**：解决问题后，花五分钟把
   「问题+解法+原因」写进笔记（不发表，
   就是记）—— 本站一半文章来自这里；
2. **想法速记**：通勤/洗澡时冒出的念头，
   手机备忘录一句话记下（「原来 XX 是这原理」、
   「这个坑值得写」）—— 不管多小，先记；
3. **别人的问题**：issue 里、群里、同事问我的 ——
   「这个问题有三个人问过」= 值得写。

**关键：素材积累和写作完全分离。**
动笔时从「素材库」挑，不从白纸开始 —— 
白纸最吓人。

## 二、动笔：先骨架，再填肉

打开编辑器，不写第一段，**先列小标题**：

```markdown
# 标题（最后定，先占位）

## 先说结论
## 一、问题是什么（场景）
## 二、怎么解决（步骤）
## 三、坑与延伸
## 小结
```

骨架 5 分钟。然后往每个标题下「倒素材」——
像填空题，不像作文题。

**这个习惯消解了「写作焦虑」**：
面对空白文档写第一段（最难），
和往「## 二、怎么解决」下贴命令（容易）——
后者是体力活，干就完了。

## 三、初稿：允许烂

第一遍的铁律：**烂着写完，不许回头改。**

- 句子不通？写下；
- 顺序乱？标个 `TODO: 调整` 跳过；
- 想不到词？用 `XXX` 占位。

**初稿的使命是「存在」，不是「好」。**
好是改出来的。动笔时追求完美的人，
都死在第一段。

## 四、放置与修改

初稿写完，**放一天**（真的，一天）。

第二天重读，通常有两种体验：

- 「这谁写的？还挺像样」 —— 可以改了；
- 「这写的什么玩意」 —— 冷静期生效，
  你的判断回来了。删两成，顺句子。

修改清单（每次过一遍）：

```text
□ 删废话（「值得注意的是」「众所周知」全删）
□ 每段一个意思（一段说不清就拆）
□ 例子够不够（抽象处补一个具体的）
□ 标题党不（标题说清内容，别玩悬念）
□ 链接补全（引用别处的地方挂上链接）
```

## 五、发布：最后一关

本站的发布流程（git push → CI → 上线）：

```bash
git add docs/... && git commit -m "add: 新文章《XXX》"
git push
```

**发前的最后一个检查**：用手机预览一遍 ——
很多问题（代码块溢出、表格太宽）只有小屏现形。

## 六、节奏：不求多

我的实际节奏：

```text
教程/技术：每月 2-3 篇（要查证、要跑代码，慢）
随笔：      每月 1-2 篇（想清楚了写，快）
```

**一周一篇是神话，一月一篇是常态。**
本站 145 篇，写了不到一年 —— 这个速度
不快，但它**没停**。停过的号，粉丝清零；
慢着的号，攒下 145 篇。

## 七、那些「写不下去」的时刻

诚实说，也有写不动的时候。应对：

- **降低标准**：这篇就写个「速查」，
  不写深度 —— 写了就有价值；
- **换类型**：技术写不动，写篇随笔/读书笔记 ——
  保持「手在动」比写什么重要；
- **允许断更**：断更两周不可怕，
  可怕的是「断了 = 失败了 = 不写了」的心态。
  回来接着写就行，没人记着你断过。

## 八、工具不重要（但说说）

```text
Obsidian：素材和草稿（双链 + 本地）
VS Code：本站文章的最终稿（Markdown）
git：版本和发布
```

折腾过各种「写作工具」，最后发现：
**工具的影响 <5%，流程的影响 >95%。**
别在工具上找写作的借口。

## 小结

我的写作系统四步：**素材日常攒、骨架五分钟、
烂稿写完放一天、清单式修改**。加上「允许烂、
允许断、降低单篇预期」。
程序员写作的优势：**我们把「写作」当工程 ——
拆解流程，持续集成，小步发布。** 
这套路，比灵感可靠多了。
