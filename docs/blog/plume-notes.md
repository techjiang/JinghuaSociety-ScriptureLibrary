# Plume 主题用了一周，说说感受

本站是用 [VuePress 2](https://vuejs.press) + [Plume 主题](https://theme-plume.vuejs.press)
搭的，从零到上线花了一天，用了一周。写点真实体验，
优缺点都说，给想入坑的参考。

## 为什么不是默认主题

VuePress 默认主题是纯文档向。我想要的是「文档 + 博客」混合：
教程区像文档（侧边栏、层级），手札区像博客（列表、标签、归档）。
默认主题要自己攒插件才能凑出来，Plume 原生支持。

## 用下来舒服的地方

**一、collections 把内容和结构解耦了。**
配置里声明四个集合，往目录里扔 md 文件，侧边栏、列表、标签页自动生成。
写内容完全不用碰配置，这个设计非常对我胃口。

**二、加密功能真的在编译期干活。**
配一个 `rules`，指定目录加口令，构建时直接加密内容，
口令不对连字节都不下发。虽然本站后来没用它（静态加密的应用场景
确实有限，见下），但机制本身做得干净。

**三、本地搜索零依赖。**
minisearch 打包在客户端，断网可搜，不用注册 Algolia 账号。
个人站要的就是这个。

**四、首页是积木式拼装。**
hero、features、image-text、posts、profile 这些块在 frontmatter 里
挑着用，改首页跟玩乐高似的。

**五、Markdown 增强够用。**
代码分组、提示容器、代码行高亮，写技术文档正好。

## 不太舒服的地方

**一、文档有点散。**
功能挺全，但查个配置要翻好几页文档，没有一张「总配置速查表」。
我配 `collections` 的时候在文档里绕了二十分钟。

**二、autoFrontmatter 会改你的源文件。**
它能自动补 frontmatter、规范化时间格式，本来是贴心设计。
但 dev server 运行时如果你同时手动改 frontmatter，两边会打架，
真遇到过写出行重复 permalink 的鬼事。规矩就一条：
**改 frontmatter 前先停 dev**。

**三、构建体积偏大。**
Node modules 装了四百多个包（连带字体图标那些），
冷启动慢，磁盘也吃不少。有 `cache: 'filesystem'` 能缓解。

**四、新版本组合有暗坑。**
装的时候 npm 自动配了 Vite 8（rolldown 内核），
这个环境编译主题自带的 Vue 组件会报
"No fs option provided to compileScript"，因为探测不到 Node 的 `process`。
解法是在 `viteBundler` 里手动注入 fs，本站 config 里有带注释的写法。
新生态狂奔时候的阵痛，能理解，但新手遇到会懵。

## 静态加密到底能用在哪

说了要写，就得说透。Plume 的加密是**静态站加密**：构建时加密，
浏览器端验口令解密。它防的是「随手翻源码看到明文」，
防不了铁了心的人 —— 口令和加密后的内容都在浏览器手里，
真较真的，逆向只是时间问题。

所以它适合的场景是：

- **内部 Wiki 的初步隔离**：防止爬虫和搜索引擎收录敏感目录；
- **彩蛋/剧透内容**：给愿意看的人一个仪式感；
- **防君子不防小人的内部文档**：配合访问日志做审计。

不适合拿它当安全边界。本站最后没用加密，就是觉得「为了用而用」
没必要 —— 没有真正的机密内容，搞个口令反而故弄玄虚。
有价值的内容，直接公开，让搜索引擎收录，让更多人看到，更好。

## 总结

| 维度 | 评分 |
| --- | --- |
| 上手难度 | 5/5（一天上线） |
| 功能完整度 | 4.5/5 |
| 文档质量 | 3.5/5（全但散） |
| 生态成熟度 | 4/5（新版本有暗坑，但可解） |

**推荐场景**：想要「文档为主、博客为辅」，不想折腾配置的个人站。
